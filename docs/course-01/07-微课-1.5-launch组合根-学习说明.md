# 微课 1.5：launch 与组合根 — 学习说明

**时长**：约 60 分钟  
**类型**：**官方跟读 + 本实验室分层实现**（`cli` → `launch` → `build_app`）  
**先修**：M0～M2 完成；`01-微课.md` 中 1.1～1.4 已做或等价完成  

---

## 1. 本节要回答的问题

学完应能向别人说明：

1. 终端执行 `uv run octop run` 后，**先经过 CLI，再进入 `launch.py`，最后才到 uvicorn**。  
2. **`launch.py` 是唯一允许同时牵 `infra` 与 `api` 的模块**（组合根）。  
3. 你写的 **`uv run octop-mini`** 与官方 **`octop run`** 在职责上各像哪一层。

---

## 2. 本实验室 vs 官方（对照表）

| 环节 | 你的 octop-mini | 官方 Octop |
|------|-----------------|------------|
| 用户命令 | `uv run octop-mini` | `uv run octop run` |
| CLI 解析参数 / 写 config | （暂未做 CLI） | `src/octop/cli/commands/run.py` |
| 组合根：起服务 + HTTP | `src/mini/run.py` | `src/octop/launch.py` |
| 领域启动 | （下阶段才有 DB） | `infra/server.py` → `OctopServer.start()` |
| FastAPI 应用 | `src/mini/api/main.py` | `api/app.py` → `build_app(srv)` |
| 配置 / 路径 | `infra/config.py` + `PathLayout` | `config.py` + `infra/utils/paths.py` |

**本课重点**：把 `mini/run.py` 当成「迷你版 `launch.py`」来读官方真身，而不是再去堆 mini 功能。

## 4. 推荐步骤（60 分钟拆法）

### 4.1 画调用链（20 min）

在白纸或笔记里画两条链：

**A. 官方**

```text
octop run → run.py（bind） → launch.run_foreground_blocking
  → OctopServer.start() → build_app(srv) → uvicorn.serve
```

**B. mini**

```text
octop-mini → run.main → load_config + PathLayout
  → uvicorn.run("mini.api.main:app", ...)
```

用箭头标出：**谁创建 Server、谁创建 FastAPI app**。

### 4.2 动手：只观察、不改仓库（15 min）

```powershell
cd D:\study\Octop\Octop-main
uv run octop run --help
```

看 `--host`、`--port` 说明。回忆 M1：`resolve_bind` 优先级是 **CLI > env > config.json**（见精读 §3.2）。

可选：只读不改地打开 `%USERPROFILE%\.octop\config.json`，对照 `bind_host` / `port`。

```text
src/mini/cli/main.py      # Click 入口
```
